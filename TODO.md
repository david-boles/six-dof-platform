## 2. Zeroing & calibration
Design (decided 2026-11-24, David):
- Firmware computes **w = C · (c − z)** for every reading: c = 6 raw counts, z = zero offsets, C = 6×6 matrix, w = [Fx, Fy, Fz, Mx, My, Mz] in N / N·m with torques about the stand's **origin (0,0,0)** in the CAD frame. Firmware calibration is always referenced to the origin.
- **C** and **z** are writable by the UI (full 36-entry C, so a future full fit needs no protocol change), held in RAM only. Defaults at boot: z = 0, C = A · diag(k_nominal), where A = ideal geometry (column i = [sᵢ; rᵢ × sᵢ], leg unit vector and attachment point relative to the origin) and k_nominal = per-cell N/count from the load cell datasheet (k = capacity·g / (Gain · 2²³ · S), S = rated output in mV/V; ratiometric wiring, so excitation cancels). No UI options for the datasheet method; it's only the boot default.
- Zeroing = `average` (1 s) then `zero/set(mean)`; no separate zero procedure.
- Reference point for display: configurable in the UI, applied in the UI as τ′ = τ − r × F.
- Calibration storage: in the browser (`localStorage`, single device so no keying) + JSON export/import. Never written automatically: on connect the UI offers to apply a saved calibration.
- Empirical calibration (UI wizard): two 1 kg weights on the platform's 6 radially symmetric mounts, one weight per mount → at most 6 + C(6,2) = 21 load cases, all vertical. Vertical loads only excite Fz, Mx, My, so the fit is per-cell k with the CAD geometry: kᵢ = Σ fᵢcᵢ / Σ cᵢ² with f = A⁻¹w, then C = A · diag(k). A full 36-entry fit would need horizontal loads (2.6).
